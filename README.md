# 오퍼하우스 현장관리

인테리어 시공사 오퍼하우스를 위한 현장 관리 웹앱. 4단계(실행정산: 예산/지출·공수관리·자재관리)까지 완료 상태.

## 기술 스택

- Next.js 16 (App Router) + TypeScript
- Supabase (Postgres + Auth + Storage)
- Tailwind CSS v4
- @dnd-kit (공정표 드래그 순서 변경)

## 시작하기

### 1. Supabase 프로젝트 준비

1. [supabase.com](https://supabase.com)에서 새 프로젝트를 생성한다.
2. Supabase 대시보드의 **SQL Editor**에서 아래 파일들을 **순서대로** 실행한다.
   - `supabase/migrations/0001_init.sql` — 테이블 6개 + RLS 정책
   - `supabase/migrations/0002_storage.sql` — 사진 업로드용 Storage 버킷(`site-photos`) + 정책
   - `supabase/migrations/0003_storage_receipts.sql` — 영수증 업로드용 Storage 버킷(`receipt-images`) + 정책
   - `supabase/migrations/0004_labor_material.sql` — 공수관리(`labor_records`)·자재관리(`material_records`) 테이블 + RLS 정책
3. 대시보드의 **Authentication → Users**에서 관리자 계정을 이메일/비밀번호로 직접 생성한다.
   (회원가입 화면은 없음 — 관리자는 대시보드에서만 생성, "Auto Confirm User" 체크 필수)

### 2. 환경 변수 설정

`.env.local.example`을 복사해 `.env.local`로 저장하고, Supabase 대시보드의
**Project Settings → API**에서 값을 채운다.

```bash
cp .env.local.example .env.local
```

### 3. 의존성 설치 및 실행

```bash
npm install
npm run dev
```

[http://localhost:3000](http://localhost:3000) 접속 시 `/admin`으로 리다이렉트되고,
로그인하지 않았다면 `/admin/login`으로 이동한다.

## 관리자 화면 구조 (고정 로고 / 탭 통합 / 저장·취소)

- 상단 헤더("오퍼하우스" 로고)는 `/admin/*` 모든 화면에 `sticky`로 고정되어 있고,
  클릭하면 항상 현장 목록(`/admin`)으로 이동한다.
- 현장 목록에서 카드를 클릭하면 바로 탭이 있는 상세 화면(`/admin/projects/[id]`)으로
  들어간다 — 별도의 "수정" 화면은 없고, 현장 기본 정보 수정도 "현장 정보" 탭 안에 있다.
- 탭(현장정보/사진/공정표/공지사항/정산/공수관리/자재관리) 전환은 라우트 이동이 아니라
  `ProjectDetailView`의 로컬 state로만 이루어진다. `[id]/page.tsx`가 7개 탭에 필요한
  데이터를 한 번에 병렬로 조회해서 넘겨주기 때문에, 탭을 바꿔도 서버 왕복이 없다(단,
  탭을 벗어나면 그 탭의 패널은 언마운트되므로 저장하지 않은 입력은 사라진다).
- 표/행 단위로 값을 수정하는 화면(공정표, 정산 예산 항목, 공수관리, 자재관리)은 입력한
  값이 "저장"을 누르기 전까지는 서버에 반영되지 않는다. 값이 바뀌면 그 행(공수관리는
  기공/조공 칸이 있는 그 행)에 저장/취소 버튼이 나타나고, 취소를 누르면 서버 호출 없이
  마지막 저장값으로 되돌아간다.

## 사진 업로드 동작 방식

- 브라우저에서 canvas로 리사이즈(긴 변 1600px) + JPEG 압축(품질 0.82) 후 Supabase Storage에
  **직접** 업로드한다 (서버를 거치지 않아 Vercel 서버리스 함수 용량 제한을 피함).
- 업로드가 끝나면 결과 URL들을 서버 액션으로 `photos` 테이블에 기록한다.
- 업로드 한 번에 촬영일/공정 태그를 하나씩 지정하는 방식이라, 같은 방문에서 찍은 사진들을
  한꺼번에 올리는 흐름을 가정한다.
- 관리자 화면과 고객 페이지 모두 촬영일 기준으로 날짜별 헤더 아래 그룹핑해서 보여준다
  (`lib/utils/photos.ts`의 `groupPhotosByDate`를 공용으로 사용).

## 공정표 달력 뷰

- 관리자 화면은 기존 목록형 입력(드래그 순서 변경)은 그대로 두고, 같은 페이지 안에
  "목록 / 달력" 전환 탭을 추가했다 (`ScheduleView` → `ScheduleEditor`/`ScheduleCalendar`).
- `ScheduleCalendar`(`components/shared/`)는 관리자·고객 페이지가 함께 쓰는 읽기 전용
  컴포넌트다. 월 단위 그리드에 각 공정이 시작일~종료일 구간 상태별 색상 막대(완료=초록,
  진행중=테라코타, 예정=외곽선)로 표시된다. 여러 주에 걸친 공정은 주 경계에서 이어지고,
  실제 시작/종료일에서만 끝이 둥글게 처리된다.
- 날짜를 클릭하면 하단에 그날 해당하는 공정 목록이 표시된다.
- 관리자 화면은 탭을 바꿀 때마다 서버에서 최신 데이터를 다시 받아오므로, 목록에서 편집한
  내용이 달력에도 곧바로 반영된다. 고객 페이지는 항상 최신 데이터로 렌더링된다.

## 정산 (예산 / 지출)

- "정산" 탭은 `budget_items`(예산 항목)와 `expense_items`(실집행 지출)를 다룬다. 예산 항목은
  분류/항목명/계획 금액을 목록형으로 추가·수정·삭제한다(`BudgetEditor`).
- 지출은 날짜/예산 항목(선택)/협력업체/금액/메모와 영수증 이미지(선택)를 입력한다
  (`ExpenseForm`). 영수증은 사진 업로드와 동일한 방식으로 브라우저에서 압축 후
  `receipt-images` 버킷에 직접 업로드한다.
- 상단 요약(`SettlementSummary`)에서 총 예산 대비 집행률·잔액, 예산 항목별 계획/집행 비교,
  협력업체별 집행 현황을 볼 수 있다. 고객 페이지에는 노출하지 않는다(관리자 전용).

## 공수관리

- "공수관리" 탭은 날짜를 하나 선택하면(◀ ▶ 로 하루씩 이동하거나 날짜 입력으로 직접 이동,
  기본값은 오늘) 그 날짜의 공종별 표(`LaborSheet`)가 보인다. 행은 공종, 열은
  기공(기능공)/조공(보조인력)/누계다.
- 새 현장은 기본 공종 11개(`DEFAULT_LABOR_PROCESSES` — 가설.철거·전기·경량·목공·냉.난방·
  설비·타일·필름·도배·도장·바닥)로 시작한다. 공정 목록을 관리하는 별도 테이블은 없다 —
  이미 저장된 기록이 있으면 거기서 유도하고(가장 먼저 등장한 순서), 없으면 기본값으로
  시작한다. "+ 공정 추가"로 만든 공정은 로컬 화면에만 있다가, 셀에 값을 하나라도
  저장해야 다음 방문 때도 남는다. 공정명 옆 × 버튼을 누르면 그 공정의 모든 날짜·
  기공/조공 기록이 한 번에 삭제된다.
- "누계"는 프로젝트 시작일부터 선택한 날짜까지 그 공정에 투입된 기공/조공 누적 합이며
  (기공·조공은 서로 다른 누계로 분리 표시), 날짜를 넘길 때마다 자동으로 다시 계산된다.
- 기공/조공 칸에 값을 입력해도 바로 저장되지 않는다 — 그 행의 값이 마지막 저장값과
  달라지면 행 끝에 저장/취소 버튼이 나타나고, 저장을 눌러야 실제로 반영된다. 취소를
  누르면 서버 호출 없이 입력 전 값으로 되돌아간다.

## 자재관리

- "자재관리" 탭은 자재별로 카드를 하나씩 두고, 그 안에 날짜순 사용/발주 기록을 표
  (`MaterialManageList`)로 보여준다. 공수관리와 마찬가지로 자재 목록 전용 테이블은 없고
  `material_records`에 저장된 `material_name`에서 자동으로 유도된다.
- 자재명/규격·단위/날짜/수량/구분(사용·발주)/메모를 입력해 새 기록을 추가하면(`MaterialForm`)
  해당 자재명의 카드가 없으면 새로 생기고, 있으면 그 카드에 합쳐진다.
- 같은 자재라도 사용과 발주 기록의 누계는 구분해서 각각 누적 계산한다(사용은 사용끼리,
  발주는 발주끼리). 카드 하단에는 "사용 소계"/"발주 소계"를 자재 단위 그대로 표시한다.
  자재마다 단위가 달라 의미가 없는 전체 합산은 넣지 않았다.
- 표의 각 필드(날짜/구분/수량/단위/메모)는 인라인 입력이지만 바로 저장되지 않는다 — 마지막
  저장값과 달라지면 그 행에 저장/취소 버튼이 나타나고, 저장을 눌러야 반영된다.
